# DSH for Vaults

> 🌐 [English](README.md)

把 [DeepSeek Harness](https://www.npmjs.com/package/@deepseek-ai/dsh)（DSH）的原生 Web UI **内嵌进 Obsidian**。每个库（vault）一个**完全独立的内核实例**：打开哪个库，AI 工作区就是哪个库，会话历史按库沉淀、互不串扰。

**为什么值得用：**

- 🗂 **多库多实例隔离**——每个库独立端口、独立数据目录、独立会话，多个库同时开互不干扰
- 🧲 **Obsidian ⇄ DSH 双向桥接**——笔记里选中文字右键直达 DSH（按行列定位读取原文）；DSH 聊天里点一下本库文件路径又直接跳回笔记，全程零复制粘贴
- ⌨️ **快捷键不被吞**——焦点在 DSH 面板内时，你在 Obsidian 配置过的快捷键照常触发
- ⚡ **零命令行，一键从无到有**——机器没装 Node.js？连 DSH 都没有？没关系：面板一键装好独立便携运行时（约 30MB、免管理员、系统无感），DSH 内核随后自动下载、自动启动——全程实时进度、镜像兜底，新手从头到尾不碰一次终端
- 🔁 **模型配置一次配好、随处复用**——「同步模型配置」可在本机任意 DSH 实例（主实例/其它库）之间拷贝供应商与 API 凭据：增量（冲突逐项询问）或覆盖（自动备份）两种模式
- 🎛 **版本选择权归你**——只跟随官方稳定通道，检查更新确认后才安装，**绝不偷偷升级**

## 特性

- **原生 webview 内嵌**：DSH 官方界面运行在独立 Electron webview 中（登录态按库持久化、token 鉴权 Cookie 正常），与浏览器访问完全一致
- **选中内容发送到 DSH**：笔记中选中文字 → 右键（或命令面板）→ 定位行（文件路径 + 行列区间）注入 DSH 输入框，模型按定位自己读取该区域
- **点击路径跳回笔记**：DSH 聊天中显示的本库文件路径可直接点击，在 Obsidian 中打开（已打开则聚焦原标签页）；文件不存在有明确提示，库外路径与二进制文件不拦截、保持 DSH 原行为
- **快捷键透传**：命令面板（Ctrl+P）、快速切换（Ctrl+O）等 Obsidian 快捷键，焦点在 DSH 面板内照常生效——自动镜像你的快捷键配置，设置里一键开关
- **启动耗时诊断**：设置页展示最近一次启动的分段耗时（探测/Node 检测/端口/内核就绪/面板加载），一键复制详情便于反馈问题
- **面板底部留白**：0–40px 可调底部留白 + 上分割线，状态栏不再遮挡面板底部内容
- **升级数据自动迁移**：旧内核升级到当前浏览器鉴权版时自动迁移会话数据（单文件 + 分片两种存储布局均支持），历史会话无缝保留
- **升级前自动备份**：迁移前先把旧数据备份到本地目录，可自定义路径、一键在资源管理器中定位备份文件夹
- **每库独立实例**：库专属数据目录（`%LOCALAPPDATA%\dsh-obsidian\<库Hash>`）不污染笔记、不参与 OneDrive 同步，会话按库彻底隔离
- **更新确认才装**：设置内检查最新稳定版内核，弹窗确认后才安装；启动过程绝不联网改版本
- **网络镜像兜底**：npm 官方源失败自动切换 npmmirror 镜像，大陆网络更稳
- **安装进度可视化**：持续全局提示 + 等待计时，完成/失败都有明确结果通知，不会误以为装好了
- **模型配置同步（你说了算）**：从本机任一 DSH 实例（主实例或其它库）拷贝 LLM 供应商与 API 凭据到当前库——可选**增量**（并集、冲突逐项弹框裁定）或**覆盖**（整体对齐来源、写前自动备份）；由你主动触发，**绝无后台静默同步**
- **零命令行一键起步**：一台什么都没装的机器（无 Node.js、无 DSH），一键即可跑到能聊天——先自动装好独立便携 Node 运行时（约 30MB、免管理员、系统无感），DSH 内核随后自动下载并启动；全程实时进度、镜像兜底，即便 PATH 损坏也能自动命中已装实例
- **启动失败可诊断**：真实启动日志带错误尾部，超时自动清理残留进程，不再只有一句"启动超时"

## 前置条件

- Obsidian 桌面版（v1.4+，Windows）
- Node.js **不必提前准备**：检测不到（或 PATH 损坏）时，面板可一键安装独立便携运行时，或按绝对路径找到已装实例

## 安装

### 方式一：官方社区商店

设置 → 第三方插件 → 浏览 → 搜索「DSH for Vaults」→ 安装。

### 方式二：BRAT（GitHub 仓库分发，支持自动更新）

1. 安装 [BRAT](https://github.com/TfTHacker/obsidian42-brat) 插件
2. BRAT 设置 →「Add Beta plugin」→ 填入 `moozhu/dsh-obsidian` → 添加
3. 更新：BRAT 会随仓库版本自动提示更新

### 方式三：手动安装

1. 从 [Releases](https://github.com/moozhu/dsh-obsidian/releases) 下载 `main.js`、`manifest.json` 和 `styles.css`
2. 放到 `<你的库>\.obsidian\plugins\dsh-ob\` 目录下
3. 重启 Obsidian → 设置 → 第三方插件 → 启用「DSH for Vaults」

## 快速上手

1. **打开面板**：左侧丝带栏的鲸鱼图标，或命令面板（Ctrl+P）搜「打开 DSH 面板」
2. **等待启动**：面板显示「正在启动 @ 端口 ...」，就绪后自动载入 DSH 界面（首次约 10~30 秒，含 npx 在线安装内核）
3. **开始对话**：DSH 里当前工作区就是你的库目录，直接用 AI 管理笔记
4. **选区直通**：在笔记里选中一段文字 → 右键 →「发送选中内容到 DSH」，模型即可按定位读取该区域；点 DSH 回复里的库内文件路径，又能直接跳回对应笔记
5. **状态栏**：左下角显示当前实例状态（`DSH: 运行中 @ 3090`）

## 内核版本与更新策略

**默认不自动更新。** 启动只使用本地已安装的内核版本（自动选最高），不会联网改版本。

想要新版本时，到 设置 →「dsh 版本更新」：插件检查 npm 官方**稳定通道**（`latest`）最新版，弹窗确认后才安装。

- 从旧版升级时，插件会**自动迁移会话数据并先备份**，历史不丢
- 网络不稳时自动切 npmmirror 镜像完成查询/下载

## 多库行为（每库一实例）

| 场景 | 行为 |
|------|------|
| 打开库 A（首次） | 分配端口（确定性哈希 + 冲突上移），以库 A 为工作区启动 |
| 同时再开库 B | 完全独立：不同端口、不同进程、不同工作区与会话 |
| 同一库开两个窗口 | 共享同一实例（同一端口），不会重复启动 |
| 关闭库 B 窗口 | 默认随 Obsidian 关闭停止进程；会话历史保留在库专属数据目录 |
| 重开库 B | 重新拉起同端口实例，历史会话都在 |
| 端口被占 / 已有手动开的 DSH | 只认自己管理的实例；检测到占用自动换端口，不动手动启动的服务 |

## 模型配置同步（一次配置、随处复用）

本机所有 DSH 实例都是**平级**的：主实例（如桌面版，数据在 `~/.dsh`）与每个库实例。**没有后台自动同步**——何时拷、从哪拷、怎么拷，全部由你决定：

设置 → **「同步模型配置」** → 选来源（主实例或任意其它库，按库名列出）→ 选方式 → 点**立即同步**：

- **增量（默认）**：只拷本库缺的；同名项两边值不同时会弹框**逐项**问你「用来源 / 留本库」（默认留本库，取消则什么都不改）
- **覆盖**：本库供应商与凭据整体对齐来源——来源没有的会被清除（幽灵清扫）；写盘前自动备份为 `.bak-<时间戳>`

**同步范围**：LLM 供应商（`llm-pi-ai` / `llm-deepseek` 命名空间）与 API 凭据 refs。**永不同步**：每实例的登录会话记录（各实例自管）、默认模型路由（`agent-default-model`）、搜索模型（`web-search-deepseek`）、插件体系（profiles）——库级选择权留在每个库。

**无状态设计**：拷贝完成后各实例独立演化，本地删除的内容不会被任何后台同步"复活"。想让改动波及全机，从已改好的实例所在库再点一次同步即可。空库首次打开时，若本机其它实例已有配置，会有一次性的引导提示直达设置。

> 刚同步完的模型如果选不中、用不了：关闭再重新打开 DSH 面板即可（实例在启动时读取凭据）。

## 数据与隐私

- 插件只是「启动器 + 内嵌客户端」，不包含 DSH 实现，与 DSH 之间仅走本机回环（127.0.0.1），无遥测、无中转
- 会话历史、模型配置、API 凭据均保存在本机库专属目录（`%LOCALAPPDATA%\dsh-obsidian\`），不进库、不参与同步
- DSH 本身按需发起外网请求（模型 API 等），由你的任务决定

## 常见问题

- **启动超时 / 提示未检测到 Node.js**：面板可直接一键安装独立便携 Node（免管理员）；或把「dsh 可执行文件路径」手动填成 `where dsh.cmd` 的输出（或 npm 全局路径 `%APPDATA%\npm\dsh.cmd`）
- **同步完的模型选不中/用不了**：关闭再重新打开 DSH 面板（实例启动时才读取凭据）
- **自定义供应商的模型（如 ModelScope 的 `组织/模型` 格式）在面板里点不动、模型弹层打不开**：0.4.0 已知 bug（反向桥接把含斜杠的文本误判为路径吞掉了点击），**升级到 0.5.0 已修复**
- **面板空白**：确认实例状态栏显示「运行中」；若仍空白请尝试重启 Obsidian
- **首次启动慢**：正常，npx 在线拉取 DSH 包；之后秒开
- **换库后状态显示旧的**：每个库独立实例，状态栏显示的是当前窗口库的实例
- **某个快捷键在面板里不透传**：只有你在 Obsidian 快捷键设置里真实绑定的组合键才会被透传；如果它在普通 Obsidian 界面里也不生效，请先去 设置 → 快捷键 里绑定
