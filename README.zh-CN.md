# DSH for Vaults

> 🌐 [English](README.md)

把 [DeepSeek Harness](https://www.npmjs.com/package/@deepseek-ai/dsh)（DSH）的原生 Web UI **内嵌进 Obsidian**。每个库（vault）一个**完全独立的内核实例**：打开哪个库，AI 工作区就是哪个库，会话历史按库沉淀、互不串扰。

**为什么值得用：**

- 🔀 **rc / alpha 内核全兼容**——旧会话数据自动迁移，升级内核历史不丢，浏览器鉴权版（alpha）开箱即用
- 🗂 **多库多实例隔离**——每个库独立端口、独立数据目录、独立会话，多个库同时开互不干扰
- 🎛 **版本选择权归你**——稳定版 / alpha 体验版双通道自选，检查更新确认后才安装，**绝不偷偷升级**

## 特性

- **原生 webview 内嵌**：DSH 官方界面直接嵌入面板（token 鉴权直连本机回环，无代理层），与浏览器访问完全一致
- **rc / alpha 双通道兼容 + 数据自动迁移**：升级到 alpha（浏览器鉴权版）时自动迁移旧版会话数据（单文件 + 分片两种存储布局均支持），历史会话无缝保留
- **升级前自动备份**：迁移前先把旧数据备份到本地目录，可自定义路径、一键在资源管理器中定位备份文件夹
- **每库独立实例**：库专属数据目录（`%LOCALAPPDATA%\dsh-obsidian\<库Hash>`）不污染笔记、不参与 OneDrive 同步，会话按库彻底隔离
- **内核版本自选**：设置里可选「稳定版」/「alpha 体验版」通道，按通道检查最新版，发现新版弹窗确认后才安装；启动过程绝不联网改版本
- **网络镜像兜底**：npm 官方源失败自动切换 npmmirror 镜像，大陆网络更稳
- **安装进度可视化**：持续全局提示 + 等待计时，完成/失败都有明确结果通知，不会误以为装好了
- **模型配置一次配置、处处可用**：主 DSH 实例的供应商与 API 凭据单向同步到各库，新增供应商/密钥无需逐库重配
- **启动失败可诊断**：真实启动日志带错误尾部，超时自动清理残留进程，不再只有一句"启动超时"

## 前置条件

- Obsidian 桌面版（v1.4+，Windows）
- [Node.js](https://nodejs.org/zh-cn)（插件启动实例前自动检测；未安装时面板会显示下载入口）

## 安装

### 方式一：官方社区商店

设置 → 第三方插件 → 浏览 → 搜索「DSH for Vaults」→ 安装。

### 方式二：BRAT（GitHub 仓库分发，支持自动更新）

1. 安装 [BRAT](https://github.com/TfTHacker/obsidian42-brat) 插件
2. BRAT 设置 →「Add Beta plugin」→ 填入 `moozhu/dsh-obsidian` → 添加
3. 更新：BRAT 会随仓库版本自动提示更新

### 方式三：手动安装

1. 从 [Releases](https://github.com/moozhu/dsh-obsidian/releases) 下载 `main.js`、`manifest.json` 和 `styles.css`
2. 放到 `<你的库>\.obsidian\plugins\dsh-ob\` 目录下
3. 重启 Obsidian → 设置 → 第三方插件 → 启用「DSH for Vaults」

## 快速上手

1. **打开面板**：左侧丝带栏的鲸鱼图标，或命令面板（Ctrl+P）搜「打开 DSH 面板」
2. **等待启动**：面板显示「正在启动 @ 端口 ...」，就绪后自动载入 DSH 界面（首次约 10~30 秒，含 npx 在线安装内核）
3. **开始对话**：DSH 里当前工作区就是你的库目录，直接用 AI 管理笔记
4. **状态栏**：左下角显示当前实例状态（`DSH: 运行中 @ 3090`）

## 内核版本与更新策略

**默认不自动更新。** 启动只使用本地已安装的内核版本（自动选最高），不会联网改版本。

想要新版本时，到 设置 →「dsh 版本更新」：

| 通道 | 说明 |
|------|------|
| **稳定版** | npm 官方正式通道（`latest`），官方发布什么就装什么 |
| **alpha 体验版** | npm 预览通道（`alpha`），含最新能力（如浏览器鉴权 Web UI） |

- 选好通道 → 点「检查更新」→ 发现新版弹窗确认 → 安装（全程可见进度提示）
- 从旧版升级到 alpha 时，插件会**自动迁移会话数据并先备份**，历史不丢
- 网络不稳时自动切 npmmirror 镜像完成查询/下载

## 多库行为（每库一实例）

| 场景 | 行为 |
|------|------|
| 打开库 A（首次） | 分配端口（确定性哈希 + 冲突上移），以库 A 为工作区启动 |
| 同时再开库 B | 完全独立：不同端口、不同进程、不同工作区与会话 |
| 同一库开两个窗口 | 共享同一实例（同一端口），不会重复启动 |
| 关闭库 B 窗口 | 默认随 Obsidian 关闭停止进程；会话历史保留在库专属数据目录 |
| 重开库 B | 重新拉起同端口实例，历史会话都在 |
| 端口被占 / 已有手动开的 DSH | 只认自己管理的实例；检测到占用自动换端口，不动手动启动的服务 |

## 模型配置共享（设置一次、处处可用）

你的**主 DSH**（例如桌面版 `http://127.0.0.1:3080` 那一份，数据在 `~/.dsh`）是模型**基础设施**的**唯一权威源**。插件在每次库实例启动时，从主实例**单向同步**到该库：

- **LLM 模型供应商**（`settings.yaml` 里的 `llm-pi-ai`、`llm-deepseek` 命名空间：baseURL、模型列表、路由配置）
- **API 凭据**（`.credentials.yaml`）

新增一个供应商 / API key 后，只要**打开（或重开）**任意库面板即可用——**每个库无需重复配置**（DSH 会热重载 `settings.yaml`）。

**刻意不同步（各库保留自己的选择）**：

- **默认模型路由**（`agent-default-model`）：例如主实例用 DeepSeek、某库想默认用 GPT / MiMo
- **搜索模型**（`web-search-deepseek`）：每个库各用各的搜索模型
- **插件体系**（profiles / node_modules）：不同库可用不同插件集

冲突处理：provider / 凭据字典做**并集合并**（库独有的保留、两边都有的以主覆盖、主新增的补进库）；方向固定**主 → 库单向**，库内的改动不会回写主实例。

## 数据与隐私

- 插件只是「启动器 + 内嵌客户端」，不包含 DSH 实现，与 DSH 之间仅走本机回环（127.0.0.1），无遥测、无中转
- 会话历史、模型配置、API 凭据均保存在本机库专属目录（`%LOCALAPPDATA%\dsh-obsidian\`），不进库、不参与同步
- DSH 本身按需发起外网请求（模型 API 等），由你的任务决定

## 设置项

| 设置 | 说明 |
|------|------|
| dsh 可执行文件路径 | 留空自动探测（npm 全局 → 管理目录 → npx 缓存 → 在线 npx）；探测失败才需手动填 |
| dsh 版本更新 | 通道下拉（稳定版 / alpha 体验版）+ 检查更新按钮；确认后才安装 |
| 数据备份目录 | 升级迁移前自动备份旧数据；留空用默认目录（显示具体路径），📁 一键在资源管理器定位备份文件夹 |
| 基础端口 | 端口池起点（默认 3090，避开桌面版常用的 3080） |
| 打开 Obsidian 时自动启动 | 打开库就自动拉起实例 |
| 关闭 Obsidian 时停止实例 | 关窗即释放内存；关闭则常驻后台、下次秒开 |
| 面板位置 | 右侧边栏 / 左侧边栏 / 新标签页 |

## 常见问题

- **启动超时**：检查 Node.js 是否安装；把「dsh 可执行文件路径」手动填成 `where dsh.cmd` 的输出（或 npm 全局路径 `%APPDATA%\npm\dsh.cmd`）
- **面板空白**：确认实例状态栏显示「运行中」；若仍空白请尝试重启 Obsidian
- **首次启动慢**：正常，npx 在线拉取 DSH 包；之后秒开
- **换库后状态显示旧的**：每个库独立实例，状态栏显示的是当前窗口库的实例
